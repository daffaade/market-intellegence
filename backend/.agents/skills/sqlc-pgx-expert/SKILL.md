# SQLC + PGX/v5 Expert Guide

## Overview
Build blazing fast, type-safe database access in Go using pure PostgreSQL queries and `sqlc` code generation paired with `github.com/jackc/pgx/v5`. Avoid heavy ORMs (like GORM) to prevent hidden queries, N+1 performance bottlenecks, and opaque reflection.

```
       +--------------------+       +---------------------+
       | schema/*.sql       |  -->  | sqlc generate       |
       | query/*.sql        |       | (compiles raw SQL)  |
       +--------------------+       +---------------------+
                                               |
                                               v
                                    +---------------------+
                                    | db/models.go        |
                                    | db/query.sql.go     |
                                    | (100% type-safe Go) |
                                    +---------------------+
```

---

## The Core Philosophy

1. **SQL First**: Schema and queries are authored in raw PostgreSQL syntax.
2. **Type Safety via Generation**: `sqlc` parses SQL schemas and generates idiomatic, zero-reflection Go code.
3. **PGX/v5 Native Driver**: Utilize `pgxpool.Pool` for connection pooling, binary protocol performance, and clean transaction handling.
4. **Idempotent Migrations**: Database changes must be versioned and runnable via migration tools (e.g. `golang-migrate` or `goose`).

```yaml
version: "2"
sql:
  - engine: "postgresql"
    schema: "db/migrations"
    queries: "db/queries"
    gen:
      go:
        package: "db"
        out: "db/sqlc"

        emit_json_tags: true
        emit_prepared_queries: false
        emit_interface: true
        emit_exact_table_names: false
        emit_empty_slices: true
```

## Query Authoring Patterns

### 1. Basic CRUD Queries (`db/queries/stocks.sql`)

```sql
-- name: GetStockBySymbol :one
SELECT symbol, company_name, sector, market_cap, pe_ratio, updated_at
FROM stocks
WHERE symbol = $1
LIMIT 1;

-- name: ListStocksBySector :many
SELECT symbol, company_name, sector, market_cap, pe_ratio, updated_at
FROM stocks
WHERE sector = $1
ORDER BY market_cap DESC
LIMIT $2 OFFSET $3;

-- name: UpsertStock :one
INSERT INTO stocks (
    symbol, company_name, sector, market_cap, pe_ratio, updated_at
) VALUES (
    $1, $2, $3, $4, $5, NOW()
)
ON CONFLICT (symbol) DO UPDATE SET
    company_name = EXCLUDED.company_name,
    sector = EXCLUDED.sector,
    market_cap = EXCLUDED.market_cap,
    pe_ratio = EXCLUDED.pe_ratio,
    updated_at = NOW()
RETURNING symbol, company_name, sector, market_cap, pe_ratio, updated_at;
```

---

### 2. Nullable / Optional Filtering (`sqlc.narg` & `sqlc.arg`)

```sql
-- name: FilterStocks :many
SELECT symbol, company_name, sector, market_cap, pe_ratio
FROM stocks
WHERE
    (sqlc.narg('sector')::text IS NULL OR sector = sqlc.narg('sector'))
    AND (sqlc.narg('min_market_cap')::bigint IS NULL OR market_cap >= sqlc.narg('min_market_cap'))
    AND (sqlc.narg('max_pe_ratio')::numeric IS NULL OR pe_ratio <= sqlc.narg('max_pe_ratio'))
ORDER BY market_cap DESC
LIMIT sqlc.arg('limit_count') OFFSET sqlc.arg('offset_count');
```

## Database Connection & Transaction Pattern

### Initializing `pgxpool.Pool`

```go
package postgres

import (
	"context"
	"fmt"
	"time"

	"github.com/jackc/pgx/v5/pgxpool"
)

func NewPool(ctx context.Context, dsn string) (*pgxpool.Pool, error) {
	config, err := pgxpool.ParseConfig(dsn)
	if err != nil {
		return nil, fmt.Errorf("failed to parse dsn: %w", err)
	}

	config.MaxConns = 25
	config.MinConns = 5
	config.MaxConnLifetime = 1 * time.Hour
	config.MaxConnIdleTime = 30 * time.Minute

	pool, err := pgxpool.NewWithConfig(ctx, config)
	if err != nil {
		return nil, fmt.Errorf("failed to create connection pool: %w", err)
	}

	if err := pool.Ping(ctx); err != nil {
		return nil, fmt.Errorf("failed to ping db: %w", err)
	}

	return pool, nil
}
```

### Atomic Transactions with `WithTx`

```go
func (r *stockRepository) ExecuteInTx(ctx context.Context, fn func(queries *db.Queries) error) error {
	tx, err := r.pool.Begin(ctx)
	if err != nil {
		return fmt.Errorf("begin tx: %w", err)
	}
	defer tx.Rollback(ctx) // Safe: no-op if tx was committed

	qtx := r.queries.WithTx(tx)
	if err := fn(qtx); err != nil {
		return err
	}

	if err := tx.Commit(ctx); err != nil {
		return fmt.Errorf("commit tx: %w", err)
	}
	return nil
}
```

## Anti-Patterns & Pitfalls

| Mistake | Consequence | Correct Approach |
|---|---|---|
| String concatenation in SQL (`"SELECT * FROM " + table`) | SQL Injection vulnerability | Always use parameterized queries (`$1`, `$2`) |
| Modifying generated `db/*.go` files manually | Overwritten on next `sqlc generate` | Modify SQL files in `db/queries/` and regenerate |
| Forgetting `LIMIT` on unbound queries | Can crash backend on large datasets | Always require explicit `LIMIT` and pagination |
| Unindexed JSONB query in WHERE clause | Full table scan on every request | Create GIN index: `CREATE INDEX idx_gin ON table USING gin(data)` |
| Leaving transactions uncommitted or without rollback | Connections hang in pool until timeout | Always use `defer tx.Rollback(ctx)` immediately after `Begin(ctx)` |
